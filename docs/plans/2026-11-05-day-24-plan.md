# Day 24: CPT synthetic cases, v2 spec first (plan item 23)

Cadence: standard day, spec-heavy. Fresh session. Read SESSION.md,
AGENTS.md, decision-log.md, flow.md, specs 001-019 and the week-3
review first.

## Starting point
328 tests green on Python 3.10 and 3.11. Week 4 opened with the markdown
report generator (spec 019). All cases today are ICD-10-CM diagnosis
coding only (spec 001 schema: gold_codes with ICD shape, five closed
condition mappings).

## Goal
Plan item 23: extend the synthetic data model so cases can carry
procedure claims alongside diagnoses - a v2 case schema (spec 020) that
adds CPT-flavored procedure codes to a case without disturbing the v1
diagnosis cases, the frozen spec-005 runner, or any existing test.
Scope for the day: schema + loader + a small synthetic CPT case set.
Auditing them is item 24 (day 25).

## Constraints
- Tests first (red locally), frozen once written; implementation pushed
  before new tests. Existing 328 tests unchanged; v1 cases keep parsing
  unchanged.
- LICENSING CAUTION: CPT descriptions are AMA-copyrighted, unlike the
  public ICD-10-CM titles used so far. Do NOT commit CPT code
  descriptions or a CPT lookup table without a verified
  license-compatible source. Consider HCPCS Level II (CMS-published) or
  clearly synthetic placeholder codes as the v2 vocabulary; verify
  provenance before choosing and log the decision with the source.
  No invented code-to-description mappings without a verified source
  (standing rule).
- Synthetic and identifier-free content only; offline-first, no live
  provider call, spend, or key request.
- Spec 020 first: v2 schema fields, validation, relationship to v1.
